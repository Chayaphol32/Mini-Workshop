# Mini Workshop Design: Coffee Member Rewards

วันที่: 2026-09-13

## 1. เป้าหมาย

สร้างเว็บแอปสำหรับร้านกาแฟเพื่อจัดการสมาชิกและแต้มสะสมแทนบัตรกระดาษ โดยใช้ PHP, MySQL และ PDO ให้สอดคล้องกับโจทย์ Mini Workshop ในเอกสาร Lab 7

ขอบเขตของรุ่นนี้มีสมาชิก การค้นหา การแก้ไขข้อมูลสมาชิก การบันทึกยอดซื้อ การคำนวณแต้ม การดูประวัติ และการยกเลิกรายการซื้อ ยังไม่รวมเมนูกาแฟ สต็อก การรับชำระเงิน หรือระบบล็อกอินลูกค้า

## 2. แนวทางที่เลือก

### แนวทาง A: Plain PHP หลายหน้า + PDO (เลือกใช้)

แยกหน้าเว็บตามหน้าที่ของโจทย์ ใช้ GET สำหรับค้นหาและเปิดรายการ ใช้ POST สำหรับเพิ่ม แก้ไข และยกเลิก พร้อม Redirect หลังทำรายการสำเร็จ

ข้อดีคือสอดคล้องกับบทเรียน Lab 7, ตรวจสอบได้ง่าย, ใช้งานกับ XAMPP ได้โดยไม่ต้องติดตั้ง framework เพิ่ม และเหมาะกับการสาธิตทีละฟังก์ชัน

### แนวทาง B: MVC ขนาดเล็ก

แยก controller, model และ view ชัดเจนกว่า แต่มีโครงสร้างและไฟล์เพิ่มเกินความจำเป็นสำหรับ Mini Workshop รุ่นแรก

### แนวทาง C: Single Page + AJAX

ประสบการณ์ใช้งานลื่นไหลกว่า แต่ไม่ตรงกับวัตถุประสงค์การฝึก GET/POST และทำให้การสาธิต Prepared Statement กับ Redirect ซับซ้อนขึ้น

## 3. โครงสร้างระบบ

ไฟล์หลักจะอยู่ที่โฟลเดอร์โปรเจกต์ LAP7 โดยมีโครงสร้างดังนี้

```text
coffee_db.sql
config/
  database.php
includes/
  functions.php
  header.php
  footer.php
assets/
  style.css
index.php
member_create.php
member_edit.php
purchase.php
member_detail.php
README.md
```

หน้าที่ของแต่ละหน้า:

- `index.php`: แสดงรายชื่อสมาชิก เลขสมาชิก ชื่อ เบอร์โทร แต้มรวม ระดับ และช่องค้นหา
- `member_create.php`: สมัครสมาชิก ตรวจเลขสมาชิกซ้ำ และบันทึกสมาชิกใหม่
- `member_edit.php`: อ่านข้อมูลเดิมและแก้เฉพาะชื่อกับเบอร์โทร ไม่ให้แก้เลขสมาชิกหรือแต้มโดยตรง
- `purchase.php`: ค้นหาและเลือกสมาชิก กรอกยอดซื้อ แสดงแต้มที่จะได้รับก่อนยืนยัน และบันทึกรายการ
- `member_detail.php`: แสดงข้อมูลสมาชิก แต้มรวม ระดับ ประวัติซื้อ และปุ่มยกเลิกรายการที่ยัง active
- `config/database.php`: เปิดการเชื่อมต่อ MySQL ด้วย PDO และ UTF-8
- `includes/functions.php`: ฟังก์ชัน escape, ตรวจ ID, คำนวณแต้ม, คำนวณระดับ, flash message และ helper ที่ใช้ร่วมกัน
- `assets/style.css`: ธีมร้านกาแฟ ตาราง ฟอร์ม ปุ่ม สถานะ และ responsive layout

จะไม่ทำ hard-delete สมาชิก เพราะจะทำให้ประวัติการซื้อสูญหายและไม่ได้ระบุเป็นหน้าที่แยกใน Mini Workshop การลบในระบบนี้หมายถึงการยกเลิกรายการซื้อ โดยเปลี่ยนสถานะเป็น `cancelled`

## 4. แบบจำลองฐานข้อมูล

### ตาราง `members`

| คอลัมน์ | ชนิด | กติกา | ความหมาย |
|---|---|---|---|
| `id` | INT UNSIGNED | PK, AUTO_INCREMENT | รหัสภายใน |
| `member_no` | VARCHAR(20) | UNIQUE, NOT NULL | เลขสมาชิกที่พนักงานใช้ค้นหา |
| `name` | VARCHAR(120) | NOT NULL | ชื่อสมาชิก |
| `phone` | VARCHAR(30) | NOT NULL | เบอร์โทรศัพท์ |
| `joined_at` | DATE | NOT NULL | วันที่สมัคร |
| `created_at` | DATETIME | NOT NULL | วันที่สร้างข้อมูล |
| `updated_at` | DATETIME | NOT NULL | วันที่แก้ไขล่าสุด |

### ตาราง `purchases`

| คอลัมน์ | ชนิด | กติกา | ความหมาย |
|---|---|---|---|
| `id` | INT UNSIGNED | PK, AUTO_INCREMENT | รหัสรายการซื้อ |
| `member_id` | INT UNSIGNED | FK ไป `members.id`, NOT NULL | สมาชิกเจ้าของรายการ |
| `amount` | DECIMAL(10,2) | มากกว่า 0 | ยอดซื้อ |
| `points` | INT UNSIGNED | NOT NULL | แต้มที่ได้ตอนบันทึกรายการ |
| `status` | ENUM | `active` หรือ `cancelled` | สถานะรายการ |
| `purchased_at` | DATETIME | NOT NULL | วันเวลาที่ซื้อ |
| `cancelled_at` | DATETIME NULL | ว่างได้ | วันเวลาที่ยกเลิก |

แต้มจะถูกบันทึกแยกในแต่ละรายการด้วย `FLOOR(amount / 10)` ส่วนแต้มรวมจะคำนวณจากผลรวม `points` เฉพาะรายการที่ `active` เพื่อให้การยกเลิกและการคำนวณระดับทำงานถูกต้องโดยไม่แก้แต้มสมาชิกโดยตรง

ระดับสมาชิกคำนวณจากแต้มรวมปัจจุบัน:

- 0–999: `Member`
- 1,000–4,999: `Silver`
- 5,000–9,999: `Gold`
- ตั้งแต่ 10,000: `Platinum`

## 5. ลำดับการทำงาน

1. `index.php` รับคำค้นผ่าน GET และค้นจาก `member_no` หรือ `name` ด้วย `LIKE` พร้อม aggregate แต้ม active
2. `member_create.php` รับ POST ตรวจช่องว่าง รูปแบบข้อมูล และเลขสมาชิกซ้ำ จากนั้น INSERT ด้วย Prepared Statement แล้ว Redirect กลับหน้าแรก
3. `member_edit.php` ตรวจ `id` จาก GET ว่าเป็นจำนวนเต็มและมีสมาชิกจริง ดึงข้อมูลเดิมมาเติมฟอร์ม เมื่อ POST ให้แก้เฉพาะชื่อกับเบอร์โทร แล้ว Redirect
4. `purchase.php` รับคำค้นผ่าน GET เพื่อเลือกสมาชิก เมื่อ POST ให้ตรวจสมาชิกและยอดซื้อ คำนวณแต้มฝั่ง PHP แล้ว INSERT รายการด้วย Prepared Statement จากนั้น Redirect ไปหน้า detail
5. `member_detail.php` ดึงสมาชิกและประวัติด้วย `id` ที่ตรวจแล้ว เมื่อ POST ยกเลิก ให้ตรวจว่ารายการเป็นของสมาชิกเดียวกันและยัง `active` ก่อนเปลี่ยนเป็น `cancelled` เพียงครั้งเดียว แล้ว Redirect กลับหน้า detail
6. แต้มรวมและระดับจะถูกคำนวณใหม่ทุกครั้งที่แสดงผล จึงเปลี่ยนระดับได้ทั้งตอนเพิ่มและยกเลิกรายการ

## 6. Validation และความปลอดภัย

- ใช้ PDO และ Prepared Statement กับค่าจากผู้ใช้ทุกจุด
- ตั้ง connection เป็น `utf8mb4` และส่ง header เป็น UTF-8 เพื่อรองรับภาษาไทย
- escape ข้อมูลก่อนแสดงด้วย `htmlspecialchars`
- ตรวจ `id` ด้วย `FILTER_VALIDATE_INT` และตรวจกรณีไม่พบรายการ
- ตรวจยอดซื้อเป็นตัวเลขมากกว่า 0 และคำนวณแต้มด้วย PHP ไม่รับแต้มจากฟอร์ม
- ตรวจ `member_no` ซ้ำทั้งใน PHP และด้วย UNIQUE constraint ในฐานข้อมูล
- ใช้ transaction ในการบันทึกและยกเลิกรายการซื้อ
- ใช้ PRG (Post/Redirect/Get) หลัง mutation เพื่อป้องกันการส่ง POST ซ้ำเมื่อ Refresh
- ใช้ `confirm()` ก่อนยกเลิก และฝั่งเซิร์ฟเวอร์ยังตรวจสถานะซ้ำเพื่อป้องกันการยกเลิกซ้ำ
- ใช้ session สำหรับ flash message และ CSRF token ของฟอร์ม POST เพื่อเพิ่มความปลอดภัยโดยไม่เปลี่ยนรูปแบบการเรียนรู้ของโจทย์

## 7. ส่วนติดต่อผู้ใช้

ใช้โทนสีร้านกาแฟแบบน้ำตาล ครีม และเขียวเข้ม แบ่งเนื้อหาเป็น card ให้เห็นแต้มรวมและระดับชัดเจน มีสถานะรายการซื้อที่ active/cancelled ปุ่มหลักที่อ่านง่าย และรองรับหน้าจอมือถือด้วย responsive CSS

กรณีชื่อซ้ำจะแสดงเลขสมาชิกและเบอร์โทรประกอบ เพื่อให้พนักงานเลือกบุคคลได้ถูกต้อง กรณีค้นหาไม่พบหรือยังไม่มีประวัติซื้อจะแสดงข้อความแจ้งชัดเจน

## 8. เกณฑ์ยอมรับและการทดสอบ

การทดสอบหลักจะครอบคลุมกรณีจาก PDF:

| กรณี | ผลลัพธ์ที่คาดหวัง |
|---|---|
| ซื้อ 85 บาท | ได้ 8 แต้ม |
| ซื้อ 125 บาท | ได้ 12 แต้ม |
| ยอดซื้อ 0 หรือติดลบ | ไม่อนุญาตให้บันทึก |
| ค้นหาสมาชิกไม่พบ | แสดงข้อความไม่พบข้อมูล |
| สมาชิกชื่อเหมือนกัน | แสดงเลขสมาชิกและเบอร์โทรให้เลือก |
| แต้มเดิม 995 ซื้อ 50 บาท | เป็น 1,000 แต้ม ระดับ Silver |
| แต้มเดิม 4,990 ซื้อ 100 บาท | เป็น 5,000 แต้ม ระดับ Gold |
| แต้มเดิม 9,995 ซื้อ 50 บาท | เป็น 10,000 แต้ม ระดับ Platinum |
| แต้ม 1,000 ยกเลิกรายการ 5 แต้ม | เหลือ 995 แต้ม ระดับ Member |
| ยกเลิกรายการเดิมซ้ำ | ไม่หักแต้มซ้ำและแสดงข้อผิดพลาด |
| ID ผิดรูปแบบหรือไม่มีอยู่ | ไม่ทำรายการและแจ้งข้อผิดพลาด |
| Refresh หลังเพิ่ม/แก้ไข/ยกเลิก | ไม่ส่ง POST ซ้ำ |

ก่อนส่งมอบจะตรวจ syntax PHP, ตรวจ SQL import, ทดสอบเส้นทางหลักบนเครื่อง และตรวจ responsive layout ในขนาดจอ desktop กับ mobile
